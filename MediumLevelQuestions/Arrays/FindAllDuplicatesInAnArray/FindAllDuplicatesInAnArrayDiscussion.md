## First instincts.

So hands in the air for this one! I had to get help, although i always try to get as little help as possible because I think its better for learning I just could not see what it was driving at, but hopefully this will explain why. 
Of course the first instinct of any programmer when they see find duplicates here is that you get yourself a hash map so you can see what you already visited in O(1) lookup time with it and just run through the array at O(N) and whenever you get a hit on the hash map that is a duplicate. That pesky O(1) memory constraint apart from the returned array is a doozy though. So my next thought was that I would need to use the array that i was creating to store the information to send back, but i just could not think of a way to make this work without multiple passes because ideally to not use the extra space you would still need multiple array traversals to find each duplicate meaning it is O(N^2) time complexity. So honestly it did not even occur to me to use the inputted array itself. I guess this is because in an industry setting you would for the most part not want a function that edits the array itself whilst just performing some form of check on it. So full disclosure I asked AI to give me hints on this one without giving it away to me and it taught me the basic principles of negative marking. Honestly it feels somewhat gimmicky to this question in particular as it requires the very specific restraints that the values be between 0 and n and that there only be one or two of each, but it did help me remember that you can change the array itself to solve these problems.

## findDuplicatesNegativeMarking  

So this is the solution i was hinted at but note that I actually WROTE the code myself after understanding the underlying concepts. So it works because the values are between 1 and n the size of array and there can be one one or 2 of each element. You iterate over the array as normal but when you hit an element you takes its value, find that position in the array and mark it as negative, in doing this if you find that number again somewhere you can check if it is negative and if it is that means there are two of it and we add it to the return array. Once you know its relatively simple, but a neat trick nonetheless. It runs in O(n) time as it just runs through the array once and O(n) memory as we have to return an array but the rest of the memory is just the O(1) of the loop variables themselves. I also added a little extra part that returns the array back to its original state, but this does effectively double the time taken for the algorithm so it would only be relevant if it was necessary to maintain the structure, but i felt like it was good practice to do so as I don't think you would really want to edit the values in a real world scenario.
