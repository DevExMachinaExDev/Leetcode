## findAnagramsSlidingWindowArrayComparison
I get it i get it there is repeated code in there that could be extracted into its own method I know, but maybe it is the sickness on me at the time of writing but when i tried to extract it it just did not seem to work out for me today so I will clean it up on my own time. That length of code works by first scanning the string that we want to find and putting the occurences into an array of ints mapped to the 26 chars. We then do a run through the string we want to check for anagrams up to the point that it is the size of the expected anagram. Here is the clever part that prevents array traversal, at each stage that we insert a value into our comparison array we check if the value is already correct if it is it must now be wrong because we have too many now and if it was previously wrong and now correct we count it as correct now. This means we can just track if we have all 26 values in correct positions and do a check to see if our comparisons has reached 26.
The second loop essentially does the same thing but it moves the left pointer and if the value that was removed was correct it is now no longer correct and if it wasn't correct we check if it now is and add it to the total. We do this as well as updating the right pointer as we were in the first loop. It ends up being O(N) time complexity and O(1) space complexity.
