# Longest repeating character replacement discussion.

## First instincts

Hands up on this one I had to get a little help with AI after a certain point, although i did try without it and got reasonably close to the solution without it I just sort of tripped over the last hurdle. So my immediate thought with this is that it had to be a sliding window problem as by its very nature it is asking for the details of a sub array which is a window into an array. I also noticed the restraints of the problem and decided that I could track the total amount of each character visited using a fixed size array of 26. However my original solution I did not realise that we could keep the window as big as its current max and just check the next window of this size is valid. I thought that we had to move the left pointer to a valid window every single time and therefore we had to have an inner while loop that checks the char array every loop for the highest frequency value, takes that away from the sum and calculate how many of the other values there are which would have meant running through the char array every time to do these checks.
I felt that this could not be right and then after a while of trying i looked up this case, I had never even considered that the window can stay full size and just check if the highest frequency is higher but now it has opened me up to this possibility for future questions that we don't always have to have a 'Correct window' for it to be valid especially when you are trying to find a longest sequence.

## characterReplacementSlidingWindow
So this is the solution that i had AI hint to me. It essentially works by realising that the longest repeating string is just the most frequently occuring char with the others representing k. So you can essentially ignore the most frequent one and just count the others against k. The second piece of the puzzle is that when you have the most frequent the window can stay that size because we are just looking for the largest, if we only allow the window to grow when the greatest frequency is higher then this is the only time that the window is bigger and we don't hit the if statement that moves the left pointer. The rest is really just about bookkeeping what is currently in our window using our array to map the values. I think the annoying part from my perspective is that i had realised that the numbers was just the highest frequency + the others and did not mean to use it this way. Ultimately this runs at O(N) for a single pass and O(1) to store the array although this is always a size of 26 which could arguably be too much.


## Thoughts
Honestly without prompting i would not have arrived at this solution. There is of course the brute force solution to this where you can check all the possible sub arrays and see which ones work and that is probably where i would start in an interview. There is a variation of this where you could use a map to store the chars which could potentially be a little better for space on smaller strings but would likely run slower than the array version given all the hash lookups. Overall i guess i generally made it to the right court, but then started playing the wrong game haha.
