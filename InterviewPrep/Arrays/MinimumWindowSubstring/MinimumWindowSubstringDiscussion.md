I feel this helped make the code a little more simple but with the tradeoff of the hash values and I originally selected it because of the need for quite large arrays and unused space to map the values when doing both upper and lower case. I guess the benefit is that my version is more scalable and requires no changes should the inputted values change, but at the cost of hash lookups vs the arrays simple lookup table. ## minWindowHashMap
So the solution is split up into steps with comments for ease of understanding here. The first step is to populate both of the maps with the important values, for the frequency map of t we just do this directly and the s frequency map we just initialise them all to 0. This way we only have in the map exactly what we need to check. We then move our right pointer through the string and if we don't hit the map there is nothing to do with that character and we can keep it in the window, if we do find a relevant char we add it to the frequency map and appropriately update our counter with whether all the elements are correct yet. If not we just keep moving the right pointer if they are correct its time to move the left pointer to try and get the smallest window. We do this by moving the left pointer until we get a hit on the frequency array again, if we get one then it no longer contains all the necessary elements so we can start moving right again. All the while we are bookkeeping whether or not the current window is smaller than the smallest already found and if it is replacing where the pointers are for that window. In the end we return the substring in one go with whatever pointers we have. The solution is O(m + n) as we need to go through each string at least once though in a worst case we have to move through M twice once with each pointer, but that still runs at O(m + n) and techically its O(1) space complexity even though it seems that the space complexity is O(N) in reality since the constraints are on which characters can be inputted the memory for the maps can only ever be at maximum O(52 * 2) for the 52 characters and the two maps which is a constant though in best cases it is technically smaller.
